# Visual / click-to-edit features in AI coding and AI site-builder tools (as of Nov 2026)

Research date: 2026-11-09. Network note: direct fetches of ship.studio, docs.lovable.dev and docs.replit.com were blocked in this research environment, so findings for those come from search-engine snippets of the official pages plus GitHub (which was reachable). Items marked "unverified" should be checked by hand.

## Q1. ship.studio: does it let you click text and replace it? (Confirm or correct the user's finding)

### Takeaway
Partly correct, but likely out of date. Ship Studio has never offered typing directly onto the preview. However, a pull request merged on **October 21, 2026** added a **Text field in the side-panel CSS Editor**. You select an element in the preview or in the Elements tree, then type the new copy into that field, and the change is written to the source file without the AI agent. If the user tried a build from before late October 2026, they would not have seen it. Even now, it is a panel field, not inline typing on the page.

### Cited Findings
- Ship Studio is a free, MIT-licensed, local-first desktop app (Tauri 2 / Rust / React 19). It installs on macOS (Apple Silicon and Intel) and Windows x64, and Linux is not listed. You bring your own CLI agent (Claude Code, Codex, OpenCode, Cursor CLI), and no subscription or account is needed. The repo has about 294 stars, 69 forks, about 1,516 commits and 121 open issues. — [ship-studio/ship-studio GitHub README](https://github.com/ship-studio/ship-studio)
- The README describes visual editing as: "Select an element, change it, write custom CSS — without burning AI credits." It also has a pinnable editor panel and a Webflow-style element tree in fullscreen mode. — [GitHub README](https://github.com/ship-studio/ship-studio)
- Git features: one-click repo creation and publishing, **PR submission with AI-generated titles and descriptions**, a merge-conflict resolution UI, snapshots and backups, and one-click Vercel deploys (staging or production) with auto-deploy on push. Plugins, agent skills, MCP config and a Plugin SDK are included. — [GitHub README](https://github.com/ship-studio/ship-studio)
- **PR #1130, "Improve CSS Editor cascade controls and selected-element settings"**, was opened Oct 19, 2026 and merged Oct 21, 2026. It adds a "Text" field for text-bearing tags that lets users "modify text on the page without interacting with the Preview or with code." It does "source-backed text and tag updates" with "source-preserving tag replacement" and text-entity encoding. The Text section appears only for text-focused or custom tags, not for layout containers like `div` or `section`. — [PR #1130](https://github.com/ship-studio/ship-studio/pull/1130)
- Known caveats raised in PR #1130's review comments: text saves can fail after you edit an attribute on the same line (stale source position), and swapping tags in React/Next.js projects could crash Fast Refresh. The PR page does not show these were fixed. The review comments mention React/Next.js and Astro/plain HTML projects. — [PR #1130](https://github.com/ship-studio/ship-studio/pull/1130)
- PR #1089 added more controls to the Elements panel (expand/collapse tree, tag icons). — [PR #1089](https://github.com/ship-studio/ship-studio/pull/1089)
- Third-party reviews say it targets freelancers and designers who want no-code simplicity without platform lock-in. — [everydev.ai listing](https://www.everydev.ai/tools/ship-studio); [ship.studio](https://www.ship.studio/)

### Inferences
- The edit is deterministic, because it is a source rewrite by the app rather than by the LLM ("without burning AI credits"). It lands in the local working tree, and the user then commits or opens a PR through Ship Studio's git UI. In effect, several copy edits can be batched into one PR, since PRs are made from the working tree, but there is no dedicated batched-edit "review queue."
- Ship Studio works on any local repo the user opens. It is not limited to projects created in the app.
- Copy that lives in JSX expressions, props, i18n files or a CMS probably cannot be edited this way. The PR only covers "safe direct text."

### Gaps
- I could not fetch ship.studio or RELEASE_NOTES.md to confirm which public release version ships the Text field.
- I could not confirm whether you can trigger editing by clicking text in the preview or only by selecting in the Elements tree. The PR says "without interacting with the Preview," which suggests the panel workflow.

## Q2. Which tools support click-on-text-to-edit inline, and on which projects?

### Takeaway
True inline text editing with no AI involved is common in **hosted AI app builders**: Lovable, Bolt, v0, Replit, and also Framer and Webflow. But it only works on projects that live inside that platform. For **arbitrary existing repos**, the options are narrower: Onlook (Next.js + Tailwind), Builder.io Fusion (connects to GitHub/GitLab/etc., commits or opens PRs), Tempo Labs (React), Ship Studio (panel field, local repo), and small dev-only plugins such as Opace's Astro Visual Editor. IDE tools such as Cursor, Windsurf, Claude Code desktop and Stagewise let you *select* an element, but the edit is then done by the AI agent.

### Cited Findings
**Hosted AI builders (project must live in the tool)**
- **Lovable Visual Edits**: an "Edit text inline" toolbar button (shortcut T) for typos, headlines and labels without a prompt. The free allowance is quoted inconsistently across Lovable's own docs: 100 free inline text edits per user per day plus a 2,000 per workspace per day cap on one page, and "500 edits per IP per 24h" on another. Beyond the limit, edits consume credits. — [Lovable docs: Design](https://docs.lovable.dev/features/design); [Lovable docs: Preview toolbar](https://docs.lovable.dev/features/preview-toolbar); [Lovable blog: Introducing Visual Edits](https://lovable.dev/blog/introducing-visual-edits) (date not captured; launched 2025)
- Lovable GitHub sync is two-way on a single branch, by default `main`. Lovable edits are committed to that branch, not opened as PRs. — [Lovable docs: GitHub integration](https://docs.lovable.dev/integrations/github). The claim that "every prompt commits to main" comes from a third party. — [RapidDevelopers guide](https://www.rapidevelopers.com/github-for-non-tech/how-to-keep-github-in-sync-with-lovable-updates)
- **Bolt.new Visual Edits**: select an element and double-click the text to edit it. Edits are **batched** and processed together when you click "Save changes." — [Bolt support: Visual Edits](https://support.bolt.new/building/visual-edits); [Bolt blog: Visual Edits](https://bolt.new/blog/visual-edits). The earlier "Visual Inspector" (Feb 2025) only selected elements for prompting. — [AlternativeTo news, Feb 2025](https://alternativeto.net/news/2025/2/bolt-introduces-the-visual-inspector)
- **v0 Design Mode**: the Design Panel can "directly edit the text content of an element," and panel adjustments do not consume v0 tokens. — [v0 docs: Design Mode](https://237.v0.build/docs/design-mode); [Vercel community: Introducing Design Mode](https://community.vercel.com/t/introducing-design-mode-on-v0/13225). The newer version requires "Apply," which creates a new chat version with a diff you can review or revert. Some users complain that simple edits now cost credits. — [Vercel community thread](https://community.vercel.com/t/new-design-mode-why-do-simple-edits-now-require-ai-credits/44083); [persist edits thread](https://community.vercel.com/t/how-to-save-and-persist-edits-in-v0-design-mode/36625/12)
- **Replit Visual Editor**: click a text element and type. Simple text edits apply directly to source without using AI credits. Composite elements (several sub-elements) cannot be text-edited directly. — [Replit docs: Visual editor](https://docs.replit.com/design/visual-editor) (via search snippet)
- **Framer**: On-Page Editing lets you update text and CMS content from the rendered page, aimed at content editors. Competitor sources say Framer has no code export. — [Framer Academy: On-Page Editing](https://www.framer.com/ja/academy/lessons/on-page-editing); [Kleap comparison](https://kleap.co/framer-vs-webflow) (competitor). **Webflow** has an Editor/canvas content editing and exports HTML/CSS on paid plans, but not React. — [Kleap comparison](https://kleap.co/framer-vs-webflow) (competitor source)

**Tools that work on existing repos**
- **Onlook** (onlook-dev/onlook): Apache-2.0, about 27.2k stars. It is an open-source visual editor for Next.js + Tailwind that edits the live DOM and writes changes back to code, with AI chat, checkpoints and branching. A hosted app at onlook.com is in early access via waitlist. — [GitHub](https://github.com/onlook-dev/onlook). Third-party reviews say double-clicking edits text. Onlook's own help says double-click jumps to source code and suggests hardcoded text is faster to edit in code. — [Onlook help: Code editor](https://help.onlook.com/en/articles/6-code-editor); [BrightCoding review](https://prompts.brightcoding.dev/blog/onlook-the-revolutionary-visual-react-editor). It can import GitHub repos (they run in a sandbox) and create PRs, per a competitor comparison. — [frontman.sh vs Onlook](https://frontman.sh/vs/onlook/). Pricing claims conflict, and a July 2025 report of $100/month for 400 messages is probably outdated. — [itsfoss news](https://itsfoss.com/news/onlook/); [onlook.com/pricing](https://www.onlook.com/pricing)
- **Builder.io Fusion**: connects to GitHub, GitLab, Bitbucket or Azure DevOps repos and "lets anyone on the team create Pull Requests directly to your codebase using a visual editor" when Commit Mode is set to Pull Requests. In a PR, reviewers can tag @builder-bot to make follow-up commits. It is explicitly marketed to marketers, designers and PMs. — [Builder docs: Projects overview](https://www.builder.io/c/docs/fusion-projects-overview); [Builder docs: Git providers](https://www.builder.io/c/docs/projects-git-providers); [Builder for marketers](https://www.builder.io/for/marketers). Caveat: an undated Product Hunt comment says it could only visually edit pages created in Builder. — [Product Hunt: Fusion 1.0](https://www.producthunt.com/p/builder-io/fusion-1-0)
- **Tempo Labs**: a "Visual Editor for React" with two-way visual and code editing that can import existing React codebases. Pro is reportedly $20/month (third-party figure, unverified). — [Product Hunt](https://www.producthunt.com/products/tempo-labs/launches); [Subscribed.fyi](https://subscribed.fyi/tempo/)
- **Subframe**: one-way design-to-code. Its drag-and-drop editor generates React + Tailwind **programmatically (not by AI)**, synced via CLI or MCP. It does not edit an existing site's copy in place. — [Subframe docs: Design to code](https://docs.subframe.com/concepts/design-to-code)
- **Opace Astro Visual Editor**: open source, dev-only and source-aware. You change text on the rendered page, and it writes to source files before you commit. — [Opace](https://opace.agency/tools/astro/visual-editor/) (surfaced in search; not deeply verified)

**IDE and agent tools: select an element, then the AI edits**
- **Cursor** 2.2 Browser visual editor (Dec 11, 2025): Select element plus a Figma-style sidebar for layout, typography, spacing and colors, and you can describe changes to the agent. Forum users say selecting mainly adds the element to chat context, and they request click-to-source. — [Cursor blog](https://cursor.com/blog/browser-visual-editor); [Cursor forum](https://forum.cursor.com/t/cursor-2-2-visual-editor-for-cursor-browser/145958); [click-to-source request](https://forum.cursor.com/t/click-to-source-from-browser-visual-editor-inspect-open-file-line/146166). No 2026 update found.
- **Windsurf / Devin Desktop Previews**: a "Send element" button inserts the selected React or HTML element into the Cascade prompt as an @mention. It does not edit text directly. — [Windsurf docs: Previews](https://docs.windsurf.com/windsurf/previews); [Devin Desktop docs](https://docs.devin.ai/desktop/previews)
- **Claude Code desktop** (Feb 20, 2026): starts dev servers and previews apps, and you can "select visual elements in the preview and pass feedback directly to Claude." Claude makes the edit, not the user. — [Anthropic blog](https://claude.com/blog/preview-review-and-merge-with-claude-code); [azukiazusa.dev](https://azukiazusa.dev/blog/claude-code-preview). Builder.io (a competitor) argues this is "not a visual editor." — [Builder blog](https://www.builder.io/blog/claude-code-visual-editor). There is also a separate `/design` skill research preview (Aug 2026) for UI artboards. — [blakecrosley.com](https://blakecrosley.com/blog/claude-code-design-skill)
- **Stagewise**: it began in April 2025 as an open-source browser toolbar where you click elements and comment to prompt an IDE agent. It is now "an open source agentic IDE for developers," AGPL-3.0, about 6.8k stars, from stagewise GmbH. Its account service is being sunset at the end of November 2026. — [GitHub](https://github.com/stagewise-io/stagewise); [stagewise news, Apr 24 2025](https://stagewise.io/news/introducing-stagewise)
- **Frontman**: open source (Apache 2.0 client / AGPL-3.0), dev-server middleware for Next.js, Astro, Vite and WordPress. You chat beside the live app, and it writes source diffs. Edits go through AI, not inline typing. — [frontman README](https://cdn.jsdelivr.net/gh/frontman-ai/frontman@main/README.md); [frontman.sh](https://frontman.sh/)
- **Click-to-source dev tools** (LocatorJS, Click To Component, react-dev-inspector, nextjs-locator): Alt/Option-click an element to open its source file and line in VS Code or another IDE. They support React (LocatorJS also Preact and SolidJS) in dev mode. These only navigate to code and do not edit copy. — [LocatorJS Chrome store](https://chromewebstore.google.com/detail/locatorjs/dpploomkdkooepkpbdpjkgfnkpfhbbfp); [Click To Component](https://chromewebstore.google.com/detail/click-to-component/hdiiegojkjkgaakbdjpoaaadhnddpfdc); [nextjs-locator](https://www.pkgstats.com/pkg:nextjs-locator)
- **Vercel Toolbar Edit Mode / Content Link**: on Pro/Enterprise preview deployments, hovering CMS-backed content shows a link that opens the matching field in the headless CMS (Contentful, Sanity, DatoCMS, Payload). It uses Content Source Maps and does not edit code. — [Vercel docs: Edit Mode](https://vercel.com/docs/edit-mode); [Sanity blog](https://sanity.io/blog/visual-editing-sanity-vercel)

### Inferences
- For "a marketer edits hardcoded copy in an existing GitHub repo and it comes back as a PR," the closest commercial fit is Builder.io Fusion. Among open-source options, Onlook (Next.js/Tailwind only) and Ship Studio (local desktop, panel field, then PR via git UI) are the closest. No tool found offers inline typing on the preview + any framework + a batched PR flow for non-technical users, so the gap remains open.
- The hosted builders (Lovable, Bolt, v0, Replit) show the UX pattern non-developers expect: double-click, type, batch, save. But they are walled to their own projects. Lovable commits straight to the default branch rather than opening PRs.

- Bolt: the docs snippets did not say whether Visual Edits consume tokens, or how saved edits reach GitHub.
- Lovable: not confirmed whether inline text edits are AST/deterministic edits (the blog suggests no prompt is needed) or whether they create a separate GitHub commit.
- Builder Fusion pricing and current limits on editing non-Builder pages were not verified.
- No primary 2026 pricing pages were reachable for Onlook, Tempo or Builder.

## Q3. Deterministic vs AI edits, licensing, and audience

### Takeaway
Direct, deterministic text edits (no LLM) are offered by Ship Studio (panel), Replit (simple text), v0 Design Panel, Bolt and Lovable (inline text, within free quotas), Subframe (programmatic codegen) and Onlook (DOM to code). Cursor, Windsurf, Claude Code, Stagewise and Frontman route the edit through the AI agent. The open-source options are Ship Studio (MIT), Onlook (Apache-2.0), Stagewise (AGPL-3.0) and Frontman (Apache/AGPL). The rest are closed SaaS. Only Builder Fusion, Framer, Webflow and Lovable are explicitly aimed at non-technical editors. The others target developers or designers.

### Cited Findings
- Ship Studio: MIT, free, edits without AI credits; audience is freelancers and designers. — [GitHub](https://github.com/ship-studio/ship-studio); [everydev.ai](https://www.everydev.ai/tools/ship-studio)
- Onlook: Apache-2.0, "Cursor for designers." — [GitHub](https://github.com/onlook-dev/onlook); [Show HN](https://hackernews4u.vercel.app/item/44127653)
- Stagewise: AGPL-3.0, developers. — [GitHub](https://github.com/stagewise-io/stagewise)
- Frontman: Apache 2.0 / AGPL-3.0, dev-only; it markets a PM/designer use case. — [frontman.sh blog](https://frontman.sh/blog/edit-website-without-developer/)
- Subframe generates code "programmatically (not via AI)." — [Subframe docs](https://docs.subframe.com/concepts/design-to-code)
- Replit simple text edits apply directly without AI credits. — [Replit docs](https://docs.replit.com/design/visual-editor)
- Builder Fusion targets marketers, designers and PMs, with PR-based review. — [Builder for marketers](https://www.builder.io/for/marketers)

### Inferences
- Tools that route edits through an LLM risk unintended code changes and cost money per edit. Deterministic source edits (the Ship Studio PR #1130 approach, Replit simple edits) are safer for copy-only changes but break down on dynamic or composed text.

### Gaps
- License and pricing for Tempo Labs and Locofy were not verified from primary sources.
